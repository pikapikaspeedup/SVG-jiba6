# INK FORGE 2 — 街霸 6 / SVG 格斗创作系统

**先打开 `OPEN-ME.html`。无需安装，两个成品 HTML 都可独立离线使用。**

| 文件 | 用途 |
|---|---|
| `dist/INK-Street-Fighter-6.html` | 完整创作版：选人、对战、动作工坊、资产中心。 |
| `dist/INK-Street-Fighter-6-Player.html` | 玩家版：保留相同角色资产与战斗，只展示选人、对战入口。 |
| `docs/QUICKSTART.html` | 图文使用指南、保存位置和限制说明。 |
| `qa/forge-validation-summary.json` | 本轮测试范围、结果、成品 SHA-256。 |

这是非官方二维 SVG 同人格斗游戏。人物造型、时序和派生经过改编，不是官方三维模型、官方动作捕捉或官方帧数据。八神庵按同人客串保留，不作为《街霸 6》官方阵容介绍。

## 1. 打开就玩

创作版默认选中电脑对战、辅助操作。选 P1、选 P2，然后进入格斗场。需要检验编辑结果时，用「练习」；支持经典六键、本地双人、自动观战。

P1：WASD 移动，J/K/L 轻中重拳，U/I/O 轻中重脚，Q 招架，E 斗气冲击，F 斗气迸发，V 投技。辅助模式用 1/2/3 发三级超级必杀，H 查看原对战招式表。经典模式使用相对朝向的搓招输入；换边后方向镜像。

P2：方向键移动，小键盘 1/2/3 拳、4/5/6 脚，0 招架、小数点冲击、加号投技、小键盘 Enter 迸发。本地双人需要具有小键盘的键盘，或使用原有手柄映射。

手机有八方向摇杆和多点触控按钮。横屏对战占满视口，仍可通过画面内「选人」「INK 动作工作台」离开。触控取消、失焦、重开会清除输入，避免卡住移动。

## 2. 第一次做动作：不用改代码

1. 打开「动作工坊」，选择不知火舞 →「轻·飞翔龙炎阵」。顶部会显示实际文件路径。
2. 暂停并拖动时间轴到第 5 帧。画布中的圆点分别是两手、两脚；直接拖动前脚或前手。松开时会写入当前关键帧。
3. 切到「形体」，调整头部、手臂、腿部、胸廓、腰线、髋部或骨架长度。模型与骨架文件不混入动作文件。
4. 切到「判定」，新增攻击框；可以拖动方框，修改挂点、大小与生效帧。攻击框必须位于有效阶段。选择自定义判定后，近身攻击不再沿用原攻击框。
5. 切到「特效」，修改类型、挂点、触发时间、持续时间、颜色、比例和角度。十二类特效由帧数驱动，可反向拖动检查。
6. 点击「保存并实战」。程序保存当前模型、骨架和动作，然后进入实际练习对战并发动该招。这里运行的是同一个战斗系统，不是预录片段或另一份演示状态。
7. 返回工坊继续调整；最后「导出游戏」生成包含修改的离线 HTML。资产中心也能导出只显示选人和对战的玩家版。

支持逐帧、0.25/0.5/1/2 倍播放、镜像、剪影、骨骼叠加、前帧残影、近景、关键帧删除和 60 步撤销/重做。修改完起手/有效/收招帧后，点击「应用时序」，并保存，才会改变实际招式时间。

**自动保存开着时，编辑会在短暂空闲后保存。** 它不是自动上传，也不会在未经授权的情况下写你电脑的文件夹。

## 3. 产生的东西到底放在哪里？

### 浏览器工作副本

「保存」和自动保存先写浏览器资产库，优先 IndexedDB，回退 localStorage。浏览器禁止持久存储时，明确提示当前只在内存中运行；此时编辑/对战仍能使用，但关闭前必须导出。代码不会把内存成功冒充成磁盘保存成功。

保存带版本号，并校验整份待更新数据后再发布。持久写入失败时，旧版本不会被新的半成品替换。导出的 HTML 再次打开后，在同一个浏览器项目内有更高修订号的修改，会优先于 HTML 内嵌的旧种子。

浏览器存储不是长期备份，清理网站数据、隐私模式或浏览器回收都可能影响它。请保留导出的 HTML 或工程 ZIP。[参考 1]

### 真正的源码文件夹

资产中心 →「选择资产目录」。选源码的 **`assets/ink`**，不是整个仓库根目录。也可选空目录，再点「写入全部资产」。目录选择必须由用户授权，受浏览器、安全上下文及权限限制；接口不可用时，继续使用 ZIP/JSON 导出，不影响对战和编辑。[参考 2]

之后「保存」会同时写入该角色的 `model.json`、`rig.json`、所选动作 JSON 和修改备份。目录写入按队列执行，避免前一次保存慢于后一次而把新值覆盖成旧值。

「从目录载入」读取真实的各角色 JSON 文件，**不是只读 `project-overrides.json`**。全部资产校验通过后才应用到工程；少一个文件或某个文件损坏都会中止，不悄悄用默认值替代。读取目录会替换当前工程修改，请先备份。

每个文件使用浏览器可写流关闭提交。多文件写入不是跨文件系统事务；突然断电、权限中途撤销仍可能留下部分文件已更新。因此仍应保留工程 ZIP，或用 Git 提交作为稳定版本。

### 发给玩家 / 继续开发

「导出可玩 HTML」是带当前资产的独立成品；不需要再把 SVG 帧逐张贴回游戏。

「导出工程 ZIP」含全部 708 个 JSON 文件、修改备份、可玩 HTML 和使用说明。这是**资产工程包**；修改渲染器、规则或原画 JavaScript 时，需要本次交付的**完整源码包**。ZIP 里的 `assets/ink/project-overrides.json` 可通过工坊「导入」恢复修改。

「导出当前 SVG」仅用于静帧检查、对比和美术审阅，不是动画资源。它包含当前视口的纯矢量图形与必要的本地渐变定义。

**保存、导出、连接本地目录均不会自动上传 GitHub。** 本次交付没有写入你的 `main`。

    │       └── state-walk-forward.json …
    └── ryu / ken / chun / cammy / luke / juri / iori

├── runtime.js                        同一姿势驱动渲染与战斗判定
├── states.js                         行走 / 跳跃 / 受击 / 双人投技编排
├── renderer.js                       保留式 SVG、连续轮廓、视图与层次
├── effects.js                        十二类纯帧特效、固定节点池

当前有 **690 个独立可编辑条目：522 个战斗条目，168 个待机、状态和双人编排条目**，配套八份模型与八份骨架。轻/中/重/OD 是分别可编辑的条目，但不冒充完全不同的招式身份。

这不是“重新手画了 690 套动画”。先前 27 条独立 INK 研究动作已按起手/有效/收招阶段映射到相应战斗变体；其余基于原 Atelier 动作迁移，并标记来源。春丽旋转鹤脚蹴、嘉米螺旋箭及不知火舞的攻击轮廓另有本轮修订。旧研究用 `clips.js` 已退到 `tests/fixtures/research-clips.js`，生产运行时不再读取统一的动作大文件。

八人头部前/侧/背面、服装前后视图、身体宽度与骨架参数分开。要重画不知火舞的衣服、发型或装饰，编辑 `src/ink/art/mai.js`；不用改其他七人。通用眼口表情在 `design.js`，不是八张彼此无关的重复大图。

## 5. 运行时边界：哪些是数据，哪些仍是规则

战斗模拟以整数帧决定状态、血量、资源、实体位置、弹道和投技同步。渲染只读取状态，在必要时插值。动作中的 `rootX/rootY` 不会再额外叠加一次世界位移。

`runtime.js` 的动作采样、骨架解算与自定义判定共用同一份资产。自定义近身攻击框跟随手、脚、肘、膝、胸廓等挂点，再经过与人物相同的镜像和整体旋转转换。受击框可独立编辑。攻击框采用半开区间 `[start, end)`，不能放在起手或收招之外。

普通状态也有自己的资产：行走绑定步态周期，跳跃结合垂直速度，受击/起身绑定模拟状态年龄。双人投技由原有抓握、受害者位置和释放约束主导；改编排不会把对手留在原地播放一段无关动画。

自定义事件不执行任意代码，不暗改血量或斗气。招式 FX 最多 32 个事件，同时最多 12 个；超出节点池容量会校验报错，不丢掉后面的效果。反向拖动时间轴可重新采样效果，命中定格不会反复派发同一事件。

**仍保留的规则层**：伤害数值、招式输入解析、取消条件、资源、投射物实体、投技同步。工坊没有开放任意投射物脚本、修改伤害的事件语言、通用约束图或完整网络回滚。手动改时序和判定意味着自定义玩法；不是官方招式帧数编辑器。

人物几何仍是二维手绘 SVG 和受约束的程序轮廓，不是三维模型。极端扭转和服装透视仍需要作者修形；IK、参数与插值不会自动把所有姿势变得完美。

## 6. 不知火舞的命名与动作归属

原战斗代码的内部 ID 不是自然语言招式名，本轮没有让旧变量名继续误导角色制作。

| 对外资产名 | 内部战斗 ID 前缀 | 动作语义 |
|---|---|---|
| `kachousen` | `kachosen` | 花蝶扇，扇子投射物 |
| `hishou-ryuuenjin` | `ryuenbu` | 飞翔龙炎阵，上升翻身膝踢/踢击，不是拳头升龙 |
| `ryuuenbu` | `hissatsu` | 龙炎舞，地面转身扫炎 |
| `hissatsu-shinobi-bachi` | `shinobibachi` | 必杀忍蜂，侧翻接突进肘击 |
| `musasabi-no-mai` | `musabi` | 鼯鼠之舞，空中身体先行俯冲，不是嘉米脚先的俯冲踢 |

阳炎之舞的五枚焰库存、空中超必杀忍蜂和扇子实体规则保留在原战斗层。动作性质以卡普空公开介绍为依据，但本项目的时序、曲线、数值与特效仍是同人改编。[参考 3]

## 7. 构建与验证

仅重建成品：

```sh
python tools/build_forge.py
```

Python 3.10+，标准库即可；不需要 npm、网络、开发服务器或外部素材。`dist/` 是生成结果，不应直接手工改生成文件。仓库根目录的 `game.js` 和 `street-fighter-6.html` 保留为对战基线，**新入口是 `dist/INK-Street-Fighter-6.html`**。构建器只在内存中按明确、唯一的锚点接入新运行时；锚点丢失或重复就失败，不静默注入到错误位置。

完整测试另需 Node.js、Python Playwright 和已安装的 Chromium：

```sh
python tools/check_forge.py
```

可用环境变量 `INK_CHROMIUM` 指定浏览器路径。没有该变量时先查找系统 Chromium/Chrome，再使用已经安装的 Playwright 浏览器。测试脚本不会自动联网下载依赖。

测试包含：原数学与时钟、所有资产和绑定、真实浏览器编辑→保存→对战、导出后重新打开、ZIP CRC32、原有机制与招式回放、状态/前后投、真实双指搓招、节点复用及渐变隔离。

测试环境只覆盖无头 Chromium。因环境禁止 URL 导航，浏览器通过 `set_content` 加载相同 HTML；持久存储在该环境被拒绝，所以真实走了内存降级与导出恢复路径。原生目录授权弹窗、真实 IndexedDB 落盘没有被冒充为通过：它们的契约测试使用明确的测试替身。文件夹读写和保存仍需在使用者自己的浏览器授权。

渲染性能记录只测同步 JavaScript 更新耗时，不包含 GPU、布局与绘制，不能换算为真实手机帧率保证。测试通过也不等于官方动作全部还原或美术验收满分。
