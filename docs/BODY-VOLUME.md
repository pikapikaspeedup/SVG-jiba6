# 动作中的角色体积与遮挡

持续第七轮让肢体随动作表达容积：固定骨架之后读取短缩、深度和折弯信息，内侧收压、外侧支撑；布料出现随屈膝/弯肘增加的压褶，肌肉使用更短的关节细线。八角色沿用各自的形态参数，不统一加粗。见 [表面几何](BODY-VOLUME-GEOMETRY.md) 与 [骨架测量](BODY-VOLUME-ANATOMY.md)。

渲染把每条肢体分为原始连续表面和真实手/脚附件，再复用既有节点绘制靠前部分。手、扇子不再靠腕部 43/91 单位圆罩决定整片覆盖范围；附件直接使用自己的实际轮廓。抬腿也拥有前景层，膝或踝接近髋高时连续进入，髋根沿腿轴用 18–34 本地单位接缝渐入，站立的腰带和胯部保持原遮挡。两臂/两腿前景按分段深度均值排序；这仍是分层 2.5D 绘制，并非每像素三维自遮挡。

骨架测量只在读取时生成并冻结缓存，不改变原始关节、手足矩阵、碰撞、根位移、伤害或帧数据。模型节点在挂载后保持有界；本轮采样中最大 461 个节点，重复绘制不增长。

相关短检：64 组几何、112 组实际骨架公式不变、384 组独立手臂平面回归；八角色站姿/防御/重脚/投技共 32 组真实渲染，检查冻结重复、有限路径、根缝与实际抬腿显露。蛛俐原生单脚护架的前腿可以显露，不能把所有 idle 都误判为双脚落地。实际目视四场景含肯升龙命中、舞必杀被防。证据绑定 `qa/body-volume/checkpoint.json`。

同脚本顺序 CPU 对比：此前各角色平均约 1.17–1.32 ms，本轮约 1.43–1.55 ms；本轮 p95 为 2.0–2.2 ms。新增表面和层次确实增加绘制工作，不把这称为性能提升，也不把同步 CPU 数值当作显示 FPS、GPU 或真机结论。未做长耐久，未新增 Pro 咨询。
