# FLOW 09 迭代计划与验收边界

起点：用户提供的 FLOW 08 原始源码与 HTML。目标不是提高版本号或堆叠装饰效果，而是回答「为什么卡」「为什么背景晃」「怎么证明确实改善」。

## 三个关键问题

1. 时间所有权混乱：首绘与复绘选择了不同的插值路径；命中定格是否绘制过会影响后续输出；待机和动作图各用不同时间。目标是相同模拟状态、相同小数时间得到相同姿态，冻结、暂停、恢复不依赖绘制历史。
2. 关键路径重复工作：第一帧整段烘焙，多个轮廓重复采样，隐藏侧面仍变形，特效反复重建历史骨架。目标是按需确定性前缀计算，共享曲面与真实挂点，不降低骨架采样率、不跳人物帧，不默认减少粒子来伪装性能提升。
3. 反馈与视图耦合：镜头跟随瞬时手脚边界伸缩、位移，加上命中震屏；有意停顿和浏览器错过刷新混在一起。目标是默认舞台完全固定，柔和跟随仅为明确选项，停顿、整体速度与效果独立控制，并记录真实回调诊断。

## 落地范围

正式 game.js、运行时、骨架前缀编译、曲面生成、特效历史、镜头和工坊设置均直接修改并进入正式构建。不通过构建时字符串注入覆盖战斗函数。保留 690 份动作及 22 条路线，原判定、资源和取消条件不变；默认命中停顿改为明确标注的 fluid 档，旧 weighted/legacy 保留，整体速度默认仍为 1×。

## 验收

复现原版缺陷；全角色双向同帧重画；暂停及跳过冻结帧；顺播/倒拖前缀与完整烘焙等值；真实扇尖历史；关闭/重新打开特效的容量边界；固定镜头整段不变；全路线三种节奏与开关特效对照；旧战斗回归；桌面与移动视口、独立 HTML 导出；相同旧节奏和完整粒子密度的独立性能对照；最终构建真实持续运行；最终 ZIP 逐文件及解压重建验证。

## 不宣称的内容

不宣称变成 3D 引擎、所有动作都完美、不宣称官方节奏等价，也不保证用户设备达到某一帧率。浏览器回调间隔不是显示器实测呈现延迟；首招计时受到当前运行环境和缓存影响。对照视频是固定时钟采样的视觉证据，不作为 FPS 测试。真实帧间隔来自单独无并行浏览器负载的 rAF 基准。
