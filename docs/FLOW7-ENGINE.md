# FLOW 07 引擎接口与维护说明

## 运行路径

`tools/build_forge.py` 直接内嵌正式 `game.js` 与 `src/ink` 模块，不在构建期间替换战斗函数体。`dist/game-forge.js` 与 `game.js` 字节一致。创作版、玩家版、连段工坊和独立导出使用同一个战斗入口与同一份动作资产。

时钟的顺序是 `EngineClock.advance → simulate → actionTick → Combo.beforeStep / Input.consume → 状态与战斗 → Combo.afterStep → renderFraction`。命中定格与超级冻结消耗模拟步，但不消耗可行动作帧。慢放跳过的步也不消耗动作帧。页面暂停和隐藏时由已有时钟重置机制阻止恢复后追赶整段离开时间。

`G.tick` 是模拟步序号；`G.actionTick` 是可推进动作的序号。新的确认时间为 `attack.confirmFrame`，为空时才兼容诊断记录里的旧 `confirmTick`。不要把 `confirmFrame=0` 当作空值。取消窗口、派生准备、舞的追投／空中追击统一以 `actionTick` 计算。UI 的秒数由模拟步按 1× 的 60 Hz 标尺换算，不是 `performance.now()` 的设备帧率。

## 请求、查询与资源

`SVG_FIGHTER.decide(index, moveId)` 只返回决策；`tryMove` 不排队，`inputMove` 可排队。`decideMove` 检查交战阶段、生命、抓取、CA 条件、空地、落地、资源、派生前置、取消关系、冻结。特殊系统动作 PAR／RUSH 也不能通过直接调用越过冻结。

资源在所有前置条件通过后一次性提交；拒绝请求不能先消耗超级能量、随后才发现斗气不足。相同纯查询可供实际输入、连段窗口和“为什么不能接”共同使用。诊断与界面不得自行模拟扣血或延长木桩硬直。

`INK.Input` 保留一个最新缓冲请求，使用可行动作帧年龄，执行成功只消费一次，诊断历史最多 64 条。更改规则模式或缓冲设置会清空实战输入和连段待发请求，防止旧规则请求在新模式里突然触发。

连段教学的 `Combo.pending` 是另一种明确的一步请求：`requestStep(0|3|6)`。0F 要求当前合法，3F／6F 允许提前，但仍须一次真实按键或触摸。G 键自动重复事件与文本输入不应被当作新动作请求。

## 连携资产合同

每个动作可选增加如下字段；省略时继续使用既有分类取消规则：

```json
{
  "transitions": {
    "version": 1,
    "edges": [
      {
        "id": "fan-heavy",
        "label": "命中后接重击",
        "targets": ["sHP"],
        "on": "hit",
        "start": 0,
        "end": 12,
        "minHits": 1,
        "maxChain": 2
      }
    ]
  }
}
```

窗口是从本招最近一次确认起算的动作帧，起止均包含。`hit` 仅命中，`contact` 可以防御接触；无挥空模式。实际接触数量用 `contactHits/contactCount`，不是“已经尝试过哪些有效帧”的 `hitsDone`。否则挥空攻击尝试也可能被误认为多次命中。

每招最多 12 条边，每边最多 16 个不重复目标，所有目标必须属于同一角色并真实存在。窗口只允许 0–20 的整数，最少命中 1–20，额外链长 1–3；状态、超级必杀、投技不作为额外连携起点。ID、文本长度、未知目标、重复边、反向窗口和危险对象键都在导入时拒绝。工程整体校验完成才提交，不形成半导入。

默认额外链长 2。真实取消保持 `flowChain`，换成另一条边也不会把计数归零；自然回到空闲后再次起手是新的连携。原有分类取消、角色安装模式、派生规则优先；这个字段不是“完整白名单”，不能用空 edges 禁掉已有正常必杀取消。它也不改伤害、硬直、资源和判定范围。任意自定义边合法不等于对应真实连段一定成立，距离与硬直仍由战斗检查。

创作入口是 `INKForge.editTransitions`，通过正常草稿、保存和撤销栈提交。`INK.Schema` 与 `INK.ProjectStore` 两层检查一致。玩家模式仅隐藏规则编辑器，不是安全沙箱。

## 表现连续性

v6 已将规则姿势与表现姿势分离，并加入源空间连续骨架；这次不重写基础轨道和身体曲面。

普通地面动作自然结束时，先截取最终 `visualPose`、最终关节角度及速度，再退出攻击对象，创建有界、5 帧的表现交接。动作图后的最终表现才是交接对象，避免只承接基础轨道而把叠加层突然清零。取消时仍须在下一招首有效帧前收束，不把旧姿势带入新的主要攻击段。OD 忍蜂反弹调用正式状态切换，从而执行同一生命周期。

冻结释放有独立的 `f._inkHoldAction` 标记。已经展示的命中帧不能在 `G.hitstop` 从 1 减到 0、但动作尚未推进时被再次解释为 `N-1+alpha`。标记保持到下一次实际动作推进；暂停恢复和慢放跳步用相同原则。`gameTime` 在慢放跳步后才推进，避免肢体冻结但待机呼吸仍偷偷流逝。

本轮数值测试是有限取样下的“交接瞬间位置连续”，不是全局导数连续证明，也不是所有动作的美术质量保证。换边、落地、抓投、受击与不可达手绘目标仍需后续专门验收。

## 停顿与 FX

`INK.CombatFlow.settings`：`rhythm=weighted|legacy`，`speed=1|.85|.75|.5`，`rules=flow|legacy`，`buffer=3|6|9|12`。设置校验完成后整体提交。

| 事件 | v6 停顿预设 | 重心预设 |
|---|---:|---:|
| 轻击 | 3 | 7 |
| 中击 | 5 | 9 |
| 重击 | 7 | 12 |
| 防御 | 4 | 6 |
| 超级必杀起手 | 20 | 28 |
| 超级必杀中间击 | 6 | 4 |
| 超级必杀末击 | 6 | 14 |

单位为模拟帧。CA 起手再加 6 帧；普通多段的中间击另按 4／5 帧规则处理。`legacy` 只恢复旧停顿数值，不关闭本版 bug 修复，也不把整个游戏变回 v6。抛投、招架等独立机制未全部改成这张表，不应写成“每种接触都统一使用七项预设”。

`impact-feedback.js` 被实际 `effects.js` 命中入口调用，生成防御、打击、踢击、扇切、上挑、终结六类。形状的方向参考投影后的打击肢体；扇弧和上挑有专用方向。出生帧分为接触 0F、后续切痕 2F、余烬／花瓣 3F，与现有世界粒子共用冻结计时。减少运动模式减少后续层和闪动；关闭 FX 不改变接触与取消规则。

预算继续为世界粒子 320、世界拖尾 64、角色本地粒子每个 144、根轨迹历史每个 40、挂点缓存每个 2048、角色实例池 2。生命周期日志 256、冲击日志 128、接触日志 120、输入日志每个 64。核心形状有较高替换优先级，装饰不另开无上限池。不存在“增加统计模块就保证任意设备不卡”的结论。

## 路线、导出与版本

`Combo.validate/configure` 对路线、步骤、资源和同角色招式做原子校验。路线最多 48 步，库最多 256 条，文件导入上限 2 MiB。原 16 条逐项不变，6 条新增舞路线在 `assets/ink/combos.json`。

工坊使用真实 `A.tryMove`，仅重置时设置初始生命／资源／距离；首次接触后木桩自动防御，主动暴露断连。运行成功保存终止时刻与剩余资源，后续待机不继续篡改这次统计。更换草稿会清掉旧结果的显示，不能给新路线贴上上一轮“成功”的标签。

独立 HTML 的外层工程数据与内层可再次导出模板都携带 `comboLibrary` 和 `rhythm`。JSON 序列化对 `<` 等做安全编码，标题中的 `</script>` 只作为文本。验证覆盖两代导出和玩家版；项目 ID 独立，默认 v7 不覆盖 v6。

源码审计只称“690 份既有资产配置和轨道不变”，不称战斗运行规则完全等价；本轮本来就在修复确认时间并新增取消。完整验证入口 `tools/check_flow7.py`，源码和时长证据均绑定当前 HTML 或对应模块指纹。旧报告不自动升级成新结论。

## 保留字段注意

`Combo.summary().actions[].cost` 是旧接口保留的“出招提交后资源快照”字段，不是本招实际消耗量；当前工坊以 `initial` 与 `remaining` 展示起手和剩余资源。读取单步日志时不要将旧字段直接当成伤害或资源消费账单。
