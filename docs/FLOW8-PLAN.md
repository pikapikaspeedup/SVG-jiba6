# FLOW 08 迭代计划与验收口径

本轮从用户提供的 v7 源码和原始 HTML 开始，目标是修复“动作衔接能成立，但播放与响应仍不连续”的运行缺陷。不能用粒子数量、模块数量或连段是否成功代替动作质量证据。

## 目标一：同一模拟步内，人物和投射物采用一致时间

检查行走、跳跃、落地及附件，而不只检查攻击关键帧。落地速度、行走周期、角色根位置、招式时间和附件应同相位取样；暂停、命中定格不得继续运动。验证方式是五个显示分数取样、渲染前后物理数据对照，以及八角色双方向重复取样。原本刻意保持的起跳姿势不应被人为制造摆动。

实现：`presentation-clock.js`，正式 `simulateCore`、`renderFighter`、`Game.update` 接入；投射物位置和扇面旋转共用分数，投射物碰撞状态不变。

## 目标二：把落地、受击和倒地衔接纳入实际生命周期

不再把最后渲染缓存当作动画源状态。切换时获取真实姿势、关节角和速度，短时交接；受击躯干保留立即反馈，附件不能等整个硬直结束才响应。着地速度可以影响表现，但不能影响真实位置、落地锁、命中框、攻击恢复和资源。

实现：`state-transitions.js`；统一时钟上的姿势／角速度交接；有界的落地身体响应和附件阻尼响应。投技握持、规则换向等约束明确分流，不宣称已实现物理人体或所有状态零误差。

## 目标三：场景特效真正服从开关、冻结和容量边界

用真实解算后的整个人物生成残影；地面冲击和镜头不能留在旧生命周期里。验证关闭特效、清爽模式、暂停、定格、重置和持续出招。容量检查包含地面池、六个残影渲染器与历史事件，不只数火星。

实现：`scene-feedback.js`，并接入正式 `ghost`、`groundImpact`、`artCameraTransform` 和世界 VFX 的 render/clear 路径。

## 目标四：给爱好者一个可以复现问题的实战姿态记录

只看预制演武不足以判断连段接续。记录真实对战的两个人物和已求解的关节角，让录制、导出、导入、倒拖、整数帧重建可验证。容量与导入格式必须受限。不得称作输入回放、录像或战斗重演。

实现：`pose-replay.js`、`forge/response.js/css`；600 模拟步，事件书签，独立装扮／骨架与已解算姿态；严格 JSON 验证、8 MB 限制和原子失败；创作版与玩家版均可用。

## 不扩大范围

保留所有 690 个动作资产和 22 条路线；不新增伤害、碰撞框、硬直、取消特权或免费资源。继承 v7 的节奏设置，不声称官方等速。不接服务器、不增加外部依赖、不写远端仓库。

## 最终验收

按最终 HTML 指纹绑定新专项、原回归、独立导出、响应式 UI、原始 v7 对照及至少 25 分钟实时时钟持续运行。完整保存失败、中止、测试夹具修正和成功记录；最终源码包解压后重新构建，两份 HTML 应逐字节一致。最终数值以 `TEST-REPORT-FLOW8.md` 和 `qa/flow8/validation.json` 为准。
