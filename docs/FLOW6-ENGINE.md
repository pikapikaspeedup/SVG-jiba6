# FLOW 06 · 源空间、关节和曲面接口

## 1. 实际运行路径

构建器按固定依赖顺序内嵌正式源码，不修改游戏函数体。`game.js` 的规则求解通过 `Runtime.rig()` 使用保留的 `Rig.solveCombat()`；绘制通过 `Runtime.visual()` 和 `Runtime.visualRig()` 使用新骨架。工坊、演武、对战与独立导出共用这些模块。

```text
资产关键帧 / 基础规则姿势
  -> CompiledClip
  -> MotionGraph / 表现层与接触修正
  -> Articulation.prepare（确定性通道和关节角缓存）
  -> 表现取消交接 / 实际关节交接
  -> Anatomy.sourceRig（源空间 IK + 角度连续 FK）
  -> Anatomy.solve（整链一致投影）
  -> Renderer（共享肢体曲面、衣纹、手掌、鞋）
  -> Runtime.socket / Motion.fanSocket（同一套最终挂点）
```

以上是数据流，不是把同一个 IK 在转身前后重解两遍。基础目标经过软可达范围处理，产生固定长度的源骨；投影后的肢体允许缩短，不再以“保持投影骨长”为由把肘膝折向另一边。

## 2. 坐标约定

作者的手腕 `fw/rw` 沿用 body-local 约定；脚踝 `fa/ra` 沿用 actor-local 约定。兼容返回值 `rig.frontArm/rearArm` 仍为 body-local，腿为 actor-local。需要最终位置的调用方统一使用 `Rig.sockets(pose, rig)`，不要自己再补一次躯干变换。

`rig.anatomy.source` 保存未投影源骨；`sockets` 是最终 actor-local 位置；`projectors` 是各肢体完整投影矩阵；`depth` 给遮挡裁剪使用；`turns` 给姿态诊断使用。这些元数据不可枚举，保留原普通数组返回形态。不要使用 `{...rig}` 或 JSON 复制后期望元数据仍在；使用原结果，或重新求解。

转身角保留完整圈数。腿围绕重力轴投影，避免站立脚的高度随骨盆局部倾斜轴乱转。手掌／折扇投影源前臂的整个二维基底；即使前臂投影几乎消失，也不会通过 `atan2` 重新计算一个反向的单位向量。

## 3. `INK.Articulation`

- `prepare(pose, clipData, frame, profile)`：绑定源片段语境，对确定的源轨道执行角度／通道预编译。`frame` 是作者片段时间。
- `inherit(from, to)`：在后续生成新姿势对象时继承语境，避免应用动作层后失去源片段关联。
- `stabilize(profile, pose, rawRig)`：按缓存采样肩／胯角和肘／膝角，用源骨长度重建。保留有限的当前层／接触修正。
- `bridge(fromRig, previousRig, targetRig, nextRig, duration, dt)`：从实际源关节角和角速度建立取消交接，不将用户目标坐标误当成最终关节。
- `attachTransition(pose, transition, time)`：将交接关联到当前姿势，首有效帧前归零。
- `clear()`：编辑后清空 WeakMap 缓存；Store 的变更监听已接入。

预采样间隔 0.25F；默认肩上臂 32°/F、髋大腿 26°/F、屈曲角 38°/F 的源轨角速率上限。上限不是生物医学或动画行业标准，只是本作的可解释防跳变参数。身体转角与根部相关通道有单独上限。完整的 `yaw` 与 `spin` 不使用最短路丢弃整圈；关节角采样则在邻点间展开后限速。

这些限制抑制病态轨道，不自动重编所有动作；极端用户轨道可能因此出现相位滞后。新一帧由同一源轨道与确定缓存计算，不依赖上一帧是否真的被屏幕显示，因此反向拖动和随机查看可以重复。

## 4. `INK.Anatomy`

`solve(profile, pose)` 返回兼容 rig 加不可枚举 anatomy 元数据；`lengths(profile)` 返回四段源骨长；`skinPoint(pose, restPoint)` 用同一胸／腰／胯变换处理躯干美术；`handMatrix`、`footMatrix` 供 Renderer 与附件共同使用；`inverseTarget` 用于工坊拖动和接触目标的反向换算。

临近侧面时逆投影不适定。`inverseTarget` 对近奇异横向轴保留原作者横坐标，而不是除以接近零的系数生成巨大新关键帧。这意味着正侧面的水平拖动会受限；可转回非侧面角度编辑。

骨长误差只针对未投影的源骨。屏幕投影后看到的缩短不是骨长损坏。肩／胯根位置仍由躯干驱动，不受未声明的屏幕历史影响。

## 5. 连续曲面与部件连接

`SkinGeometry` 沿三关节中心线建立圆滑连续曲面，使用 18 个采样与半径场生成闭合外轮廓和纵向光影带。一个肢体不再由两段各有边框的胶囊拼接。

填充路径与衣纹裁剪路径一致；肘膝的可见线只是内部折痕，不是独立关节圆片。近侧手臂遮挡按沿骨段深度裁剪，不在整条手臂层级上突然前后切换。躯干与腰胯补面处理肩／髋接口；不等于一般的网格碰撞或自动拓扑修复。

护腕和绑腿在 profile 指定的源骨长上建立，随后按当前投影长度缩放。以前按首次绘制长度建衣纹，先打开正面还是侧面会得到不同结果；该初始化依赖已消除。鞋子在脚踝原点单独变换，零度是合法平放角。左右鞋尖轮廓随转角缩短，不靠突然 180° 旋转补方向。

## 6. 取消、规则与 FX

`Runtime.capture()` 从实际游戏接口采样下一招 `t=0` 和 `t=0.25`，临时视图显式清空旧交接所有权。旧做法以 outgoing pose 为缺省值，导致下一招没声明 `yaw` 时借用了上一招转角；实际播放却从中性缺省值开始，于是交接计算和绘制不一致。

当前保留基础 pose 交接、表现 pose 交接，再补实际关节交接。交接时长 `min(5, max(0, startup-1))`。零启动余量无法同时保持任意旧姿势与下一招首有效帧动作，因此该情况不承诺可见的平滑过渡；实际路线矩阵单独记录零时长样本。

受击等状态仍可立即响应规则，不给反应动作加输入迟滞。普通结束回待机不是同一条自然取消路径，不应援引取消矩阵声称所有状态边界零误差。

特效保留独立生命周期／容量管理。`Runtime.visualSample()` 和 `Motion.fanSocket()` 使用实际新 rig，避免火焰围绕旧 IK 轨迹发射。渲染补帧不推进发射器年龄；命中定格、取消后的存量粒子逻辑沿用 v5 并回归。

修复基础坐标资产可能移动按原骨骼计算的碰撞几何。这里只保证“新视觉曲面／附加关节限制不直接写入规则求解”，不保证不同资产版本的每帧碰撞坐标相同。

## 7. 资产修复与兼容

`tools/repair_flow6_assets.py` 为一次性迁移工具，不是构建步骤。仅处理标明为 `migrated-atelier` 的源轨，按真实招式登记重建同时间点的手脚坐标，保留动作绑定、其他通道和框配置；跳过已标记本轮手工重编的记录。原始前后值记录在 journal，重新运行可能没有新增修复，不应据此覆盖历史日志。

`tools/repair_flow6_holds.py` 同样是一次性迁移；`author_mai_flow6.py` 是舞的四份龙炎舞编排脚本，不适合对任意用户工程自动执行。用户导入无自动清洗。

`MotionGraph`/`Articulation` 缓存按对象身份，编辑必须通过 Store 更新或显式清理。原可编辑 JSON 格式 version 2 保持；新诊断数据不混入用户存档。旧轨道无新 metadata 也可进入新骨架，但不会自动获得新的动作编排。

## 8. 检视、回放和测试

`INKContinuityLab.open('turn'|'sHK'|'sMK'|'ryuuenbu-heavy'|...)` 使用真实 Renderer；`seek(frame)` 为作者时间，turn 模式一帧对应 2°；`state` 给出当前源骨、挂点和误差，`renderer` 为实际对象。误差指标用于几何诊断，不是艺术质量评分。关闭对话框恢复此前暂停状态和焦点，Store 更新会重建当前角色而不是继续看旧缓存。

全部检查通过 `tools/check_flow6.py` 进入。有限值矩阵、关键帧边界、实际 CTM、自然取消、战斗回归、导出和持续运行分别有独立原始 JSON。真实 v5/v6 对照使用两份 HTML，而不是模拟禁用模块。修复中失败／中止的记录保留，但不计入最终通过数量。
