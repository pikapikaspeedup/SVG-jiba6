
## 结果相关的恢复段

`src/ink/recovery-motion.js` 提供 `INK.RecoveryMotion.pose(f, source)`、只读 `inspect(f)` 及 `settings.enabled/amount`。恢复层应放在 StrikeMotion 之后、BodySupport 之前；正常 visual 与下一招 capture 的图采样使用相同顺序，之后继续使用既有 Runtime/StateTransitions 桥接。无需增加模拟接触钩子。

模块只在当前招 `t > startup + active` 且 `t < startup + active + recovery` 时表达，恢复两端为零；平方正弦包络保证端点位移与一阶速度回零。命中在恢复时间的 72% 处完成短收，剩余时间仍由原战斗恢复锁决定，不提前可行动。防御先撤回再小幅回稳，空挥保留有限过冲后归位。

结果读取当前 attack 的 `contactResult`，优先最后一次 block；否则取 hit 或 hitConfirmed，再否则为挥空。因此多段先命中再被防御按最后防御处理。飞行道具可能在收势中晚命中，本层直接排除，避免途中切换结果造成姿态突变。超级技、投技、空中、升空、捕获、airLock、upper/dive/stance/install 同样保留原特殊轨迹。

八角色的收势区别：隆沉稳胸胯回正；肯前倾追身回收；春丽腿击反向胸胯平衡；嘉米回身螺旋；卢克紧凑护下巴与后手归架；蛛俐单脚踢后反向平衡；舞侧身扇舞后手回弧；八神低重心收爪。变化只作用于胸髋、头、bob 和后护手，不写前攻击手、双脚目标、根、状态、时序、资源或判定。

有限纯函数检查：`node --test tests/move-cadence/recovery.test.js`，覆盖八角色结果区分、状态只读、攻击目标不变、活动帧不介入、首尾归零、最后接触优先与特殊路径排除。该检查不代替整轮真实战斗、桥接和截图检查。

## 启动与活动段的身体节拍

`StrikeMotion.pose(f, source)` 接管 Kinetic 原有的通用加载、释放与拖长的收势。BodySupport 同时移除重复的攻击幅值，继续负责脚支撑、步行、刹步、方向转换及安静护架，避免同一招的髋胸被多层重复放大。

身体相位采用正式每击窗口的首个整数判定帧 `startup + ceil(i * active / hits)`；胸部发力峰值就在该帧，髋提前、后肘随后，不等到活动段中途才发力。单击释放尾部最多 6 帧，长 active 代表持续判定机会，不被误当作慢发力。首击加载长度按轻重变化，轻拳集中在启动末段、重拳更早蓄力；多段技在每个后续窗口重新加载和释放，挥空保持同样节拍，不靠确认事件偷偷移动活动帧。髋相位提前，胸按基准窗口，后侧肘导向稍后跟随。模型不写手腕 `fw/rw` 或脚踝 `fa/ra`，不增加根位移、伤害、判定或动作帧。

| 角色 | 身体路径 |
| --- | --- |
| 隆 | 沉髋再立，后肘回收，保持正面拳架 |
| 肯 | 髋先向前带动，胸随后打开，后肘向上收护 |
| 春丽 | 多击间交替髋胸方向，保留轻灵开放姿态 |
| 嘉米 | 髋胸反向螺旋，后肘走斜向路径 |
| 卢克 | 躯干收紧后送肩，头与后肘回到拳击护架 |
| 蛛俐 | 踢击以髋为轴、胸反转平衡，手肘后牵 |
| 不知火舞 | 胸转与展开错相，后肘走弧线 |
| 八神庵 | 先下沉再低位前送，反向胸转与低爪肘线 |

角色区别来自相位和路径组合，不只是同一正弦的缩放。接触反馈仍由既有 StrikeFeel/Kinetic contact 层承担；StrikeMotion 不因 hit/block 改变原攻击窗口。活动结束后最多 3 帧淡出到零，不再产生独立收势周期，后续结果差异交给 RecoveryMotion。

`phase(f,t)` 可纯采样检查相位；`pose` 继承 Articulation 元数据。Runtime 的实际画面采样和取消衔接采样必须使用相同模块顺序。数学短测 `node tests/strike-motion/unit.cjs` 检查八条不同路径、每击释放窗口、有限值、腕踝目标保持不变以及只读采样；这不等于最终骨架端点或画面已完成实战验收。
