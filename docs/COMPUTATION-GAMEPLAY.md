# 计算等于游戏性：引擎演进

目标是让动作、空间和时序的计算创造玩家可以理解、练习、取舍的决策。计算结果必须进入真实对战，并且能用相同输入的对照证明它改变了结果。更复杂的动画或更多诊断数值，本身不算完成这个目标。

## 第一轮可玩切片：擦身反入

在 FLOW09 基础上新增独立的「计算对抗」实验规则。首页点击「挑战擦身反入」进入；普通对战上方也可打开设置。新环境默认保留经典规则，实验模式会明确标示。原 707 份动作、模型、骨架及路线资产没有改动。

- **X 短撤**，P2 使用小键盘减号。仅能从地面待机开始，没有无敌、霸体或免费资源。全程 24 个可行动作帧，前 8 帧每帧后退 7 个世界单位；到墙边会被限位。
- 对手的合资格普通技从活动开始到结束，玩家必须一直处于同一次短撤。整段没有任何攻击盒与身体盒重叠，且存在大于 0、至多 18 世界单位的水平分离近失，才认证擦身。玩家须实际后退至少 8 单位。
- 认证在最后活动区间和本步接触结算完成后发生，不能因一帧近失提前奖励。格挡、招架、无敌导致的不扣血不算挥空。缺失采样、换招、受击、换边、瞬移或盒拓扑变化会否决认证。
- 认证绑定这次短撤，最早下一动作步可消费，且只能在最后 4 帧收势时取消到 **K 中拳 / L 重拳**。可以提前输入缓冲。取消只用一次，离开短撤即失效，不能取消受击或命中冻结。
- 没有额外伤害加成。提前反击若打中对方收招，使用已有 PUNISH 规则；慢招或距离判断错误仍会落空或错过确反。

训练场提供三种距离、两种攻击、固定/延迟出手、1×/0.5×自选练习速度，以及保留接触计算与反馈的「擦身取消奖励」A/B 开关。示范通过真实出招、短撤与输入缓冲执行，明确标为示范，不计作玩家成绩。暂停和 N 单步沿用原模拟。

## 计算与规则的分界

`src/ink/contact-solver.js` 是无 DOM、无时钟、无副作用的数学层。对两端 AABB 的四条边做线性插值，将相交转化为四个线性不等式的交集，得到首次接触时间、代表点和法线。包含双方位移、尺寸变化和初始重叠。边界纯相切不算命中，沿用原方框严格重叠语义；末端只有相切也不计入旧活动窗。

最近距离使用欧氏距离，不扩大伤害盒。每轴分离量是三个仿射函数的最大值；分段后平方距离为二次函数，在分段端点及内部极值中求最小值。它度量的是**战斗代理盒**，不是 SVG 轮廓。

`src/ink/spacing.js` 管理模拟快照、攻击实例、几何连续纪元、完整挥空记录及短撤权限。当前连续检测与擦身认证只开放给地面、单击、无投射物、有恢复段的普通技。投技、超级捕获、空中技和多击继续走原通道，尚未宣称完成统一迁移。

稳定盒身份使用 `part`（自定义盒含资产 ID），不依赖数组顺序。新激活只在新活动姿态检测，不从起手姿态扫入；终端几何在原动作的活动结束点求值，检测的是结束之前的区间。换招、状态转换、镜像、修订切换不能连接成扫掠路径。**高速移动本身不是瞬移**，没有按位移阈值禁用连续检测。显式重定位应使用 `SVG_FIGHTER.teleport(index,x,y)` 或先调用 `INK.Spacing.invalidate(fighter)`；不要在已采样后直接改位置而不标记不连续。

`game.js` 在双方推进后统一采样，在副作用发生前分类合资格普通技的命中、格挡、招架、霸体、COUNTER 与 PUNISH。保留原来的整步互击政策；TOI 用于接触定位，不用于擅自删除同一步较晚的攻击。双方致死打击可以互击，双方源攻击保留确认；冻结取本批最大值。当前全局 hitstop 会冻结双方，因此不会在冻结期间推进扫掠或权限寿命。尚不支持独立冻结某个角色的连续接触语义。

`forge/spacing.js` 提供练习、输入按钮和反馈；训练动作由模拟步驱动，页面刷新只读结果。便携 HTML 携带实验设置，即使浏览器禁用存储也可恢复内嵌设置。

## 验证

```sh
python3 tools/build_forge.py
python3 tools/check_spacing.py --browser
# 只核对当前源码、数学测试及已有浏览器证据：
python3 tools/check_spacing.py --evidence
```

需要 Python 3.10+、Node.js；浏览器测试另需 Python Playwright 和 Chromium，可用 `INK_CHROMIUM` 指定已安装浏览器。结果写入 `qa/flow10/`，绑定当前 HTML 的 SHA-256。`qa/flow9/` 是此前版本的历史证据，不能替代新成品验收；不要重写它来制造当前通过状态。

追加复用了原引擎的 24 项合同和 8 角色共 522 条动作回放，全部通过；只调整运行器的浏览器位置与报告输出目录，行为断言未修改。记录见 `qa/flow10/inherited/`，不代表已覆盖全部 690 招的所有交互。

本轮包括数学随机密集采样对照、连续穿透、最后活动区间、身份与拓扑边界、完整挥空、无敌否决、一次性权限、冻结、绘制次数不变性、致死互击、39 条原有机制、真实按钮/键盘、移动视口及离线导出。A/B 例子中，相同短撤/中拳序列，开启取消奖励造成原有确反伤害 600，关闭时变成恢复后的普通命中 500；差异来自窗口，不是新加伤害倍率。具体记录见 `qa/flow10/reward-ab.json`。

已通过用户授权的 Chrome ChatGPT Pro 做方案设计审议。采纳了完整活动期认证、原步互击、共同快照分类、稳定形状身份和 A/B 玩法验证。没有直接照搬其全部建议：本轮保留浮点和严格相交语义，使用欧氏距离；未引入定点/有理数、独立冻结或完整回滚。这些差异必须在后续审计中继续跟踪。

## 尚未完成的长期工作

1. **玩法验证与平衡**：扩充不同角色、出手节奏和招式的可达性矩阵，加入对固定套路的反制；真实玩家能否根据距离选快拳、重拳或放弃，还需实际游玩证据。单一示范成功不等于已证明好玩。
2. **统一接触语义**：逐项迁移多击、投射物、空中、捕获与投技；补齐混合通道原子提交，避免将普通技的测试结论扩大到所有动作。
3. **可复现的对抗**：完整输入录制/重演、固定随机源、可比较的战斗状态签名；当前姿态回放不等于战斗重演。
4. **动作创作变成玩法创作**：让作者编辑接触空间和时序，立即看到射程、风险与取消的变化；拒绝把装饰弹簧或渲染噪声直接变成伤害。
5. **性能与表现一致性**：控制几何求值和事件存储成本，测量普通对战与实验模式；建立可解释的战斗代理与画面轮廓关系，逐步评估胶囊或凸多边形模型。

本轮没有证明跨平台逐位确定性、任意骨架曲线的精确连续碰撞、全部 690 招兼容、真机性能或玩法平衡。持续改进目标仍在进行。
