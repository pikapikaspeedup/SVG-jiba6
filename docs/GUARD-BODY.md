# 防御与承伤身体语言

## 身体响应

`GuardBody.response(f,p,r,now,motion)` 采样冻结的接触快照，只修改调用方的工作姿态 p。识别 guard/parry/armor 后返回 true，由 StrikeFeel 委托，避免叠加旧统一防御反应。未识别或模块关闭返回 false。时间使用 actorBirth/duration 与角色视觉时钟，不使用绘制次数。

低段防御将前腕和前肘下移，后手保持头部保护；高、中段保持较高前臂。前臂先承受压力，胸肩和髋随后传递，脚部目标保持不变。接触点只对前肘增加至多 8 单位的有界方向修正，不将手吸附到世界命中点。招架使用较短的偏转路径，躯干扭转小于普通受击。

霸体只做局部胸压缩、胸转和小幅头髋跟随，四肢目标完全保持原动作。不会假装普通受击后退，也不会停掉攻击或改变活动帧。已进入 hit/tumble/captured/down 等状态则不再显示旧 brace。普通防御反应也不能覆盖新攻击：只有 block/parry 与退出后的 idle 能继续采样护臂。

`GuardBody.pose(f,source)` 在没有有效接触反应的 block/parry 中维持护架，继承 Articulation 元数据，不与 response 重复施加。反应期间若仍处于防御，静态护架保持稳定，接触脉冲单独衰减，避免寿命结束时突然重新举手。

八角色的护架结构分别为隆的紧凑双拳、肯的前手迎挡、春丽的掌腕接招、嘉米的贴身前臂、卢克的高位拳架、蛛俐的侧身髋胸平衡、舞的持扇护架、八神的屈指低爪。差异落在前后腕肘路径与胸髋关系，不移动战斗根或改关节长度。

姿态字段 `handFront/handRear` 输出 fist/guard/claw/grip，`expression` 输出 guard/brace。手部与面部渲染由独立固定附件实现；GuardBody 不创建 SVG 节点，不修改接触快照或战斗判定。舞前手保持 grip，普通受击的 hurt 表情由渲染层优先。

### 检查边界

已完成八角色模块检查与 43 项真实接触检查：高低护架、首帧前臂桥接、反复绘制纯度，以及真实 DI 霸体伤害与攻击继续。另检查五个造型场景与三张整场截图，确认左右手单一变体、舞握扇、guard/brace/hurt 优先级与固定节点数。报告绑定本阶段成品，见 `qa/guard-body/checkpoint.json`。

## 左右独立手型与防守表情

表现层读取 `p.handFront` / `p.handRear` 的 `fist`、`guard`、`claw`、`grip`。各手分别在同一腕部锚点挂载固定 SVG 变体，逐帧仅切换 display，不创建节点或写 innerHTML。没有显式手型时仍使用原 `p.open` 兼容拳/张掌；原有角色皮肤与拳套配色保留。

护掌采用收拢指节与立掌轮廓，爪型显示弯曲指端，握持采用包住柄部的紧凑轮廓。舞的前手在扇可见时优先握持，扇根和手腕矩阵完全沿用既有锚点，避免切换护掌时看似放开扇柄。手型不改变骨架长度或战斗判定。

`p.expression='guard'` 显示专注眉形与闭口，`brace` 显示咬紧牙关；正面与侧面各有固定表情组，后脑不添加面部。Renderer 始终优先真正的 hurt，其后才采用这两个防守表达，否则继续原 rest/power。面部轮廓、头部比例和角色发型不变。

新增节点数按角色/手/头视图固定，属于挂载成本，不随战斗时长增长。造型语法检查不代替实际防守、扇柄握持与左右手独立状态的整场景审看。

本阶段保留伤害与判定规则，新增 armor 接触事件统一驱动身体、音色、短金色火花与紧凑接触形状，不误计普通命中确认/连击。同步 CPU 样本每角色 480 步、120 步预热后均值 1.16–1.39 ms，p95 2.1–2.8 ms；这不是显示帧率或耐久证明。
