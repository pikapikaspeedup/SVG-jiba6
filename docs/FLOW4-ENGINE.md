# FLOW 04 · 动作、缓冲与特效实现说明

本文以本包源码为准，描述本项目的实现合同，不是官方《街霸 6》技术或帧数据。版本 3 的历史设计说明仍在 `FLOW-ENGINE.md`；以下是本轮新增与修正的部分。

## 1. 战斗、动作与表现的边界

不可变的 `game.js` 继续保存移动、资源、招式条件、投射物、受击与命中结算。`tools/build_forge.py` 对唯一源码锚点做接线，并校验原文件 SHA-256。生成的 `dist/game-forge.js` 是构建中间物，不能当成需要手改的源文件。

一份姿势通过 `INK.Runtime.sample` 和 `INK.Rig.solveAnimation` 进入角色显示与几何采样。惯性交接在下一招的起手阶段结束，不把一个独立“显示假人”挂在原判定外。世界根位移 `rootX/rootY` 不通过动作层注入战斗位置。

发辫、腰带、纸面、火星和花瓣是表现数据。它们可以跟随攻击姿势，但不能写 `hp`、`drive`、`super`、命中数或受击时间。演武窗口只读取资产；真实连段要进入 `INK.Combo`。

## 2. 基线与三个派生时钟

| 时钟 | 负责什么 | 定格/慢动作处理 |
|---|---|---|
| `G.tick` | 原模拟步标识、原系统事件 | 命中定格中仍可能递增，不能直接用作新缓冲寿命 |
| `INK.Input.frame` | 常规输入的 9F 生存期 | 原本就处于定格，或慢动作跳过的步，不消耗 |
| `INK.VFX.time` | 世界粒子与残留拖尾寿命 | 与上述可行动步对齐；额外保留 `frozen` 标记解决最后一帧定格边界 |
| `INK.Combo.clock` | 当前路线的节拍、0/3/6F 请求窗口 | 挂在进入实际战斗更新的步上，不按屏幕刷新次数推进 |

主循环先捕获“本步开始时是否冻结”，再处理原系统。渲染只读取时钟，在允许时做小数插值。暂停或最后一个冻结步不能因为 `G.hitstop` 恰好降到零，就向前/向后采样一小段粒子时间。

`SVG_FIGHTER.renderFraction(alpha)` 是表现检查接口；不推进模拟、不产生新粒子、不生成命中。`SVG_FIGHTER.step(n)` 才是测试中的模拟推进接口。

## 3. 惯性交接

`motion.js` 中的 `bridge/apply` 把旧姿势相对新目标的差值，作为短时衰减残差叠加到新动作上。

设交接时长为 T，u = t/T，姿势差为 δ，速度差为 Δv：

```text
R(t) = δ × (1 − 10u³ + 15u⁴ − 6u⁵)
     + TΔv × (u − 6u³ + 8u⁴ − 3u⁵)
```

起点继承位置与速度；终点残差、残差速度、残差加速度归零。时长取 `min(5, startup − 1)` 的非负值；有效帧之前完全回到资产姿势。

角度只在动作交接时选择最短弧。一招内部的整圈 `spin/yaw` 仍按原轨道采样，不做逐帧角度折返。速度差设有上限；比例与扇面开度有物理范围限制，因此极端编辑会优先保证合法范围，不能把所有受限通道都宣称为无条件连续。

装饰运动使用已经发生的转身速度、旋转速度与 `meta.secondaryBeats` 的衰减脉冲。没有依赖上一屏幕帧的弹簧积分器，所以前后拖动不会积累误差。交接时额外用 8F 平滑装饰状态。

## 4. 输入不是自动连招

`SVG_FIGHTER.inputMove(i, id)` 允许明确输入进入常规缓冲；`tryMove(i, id)` 是立即尝试，不写入延迟队列。正常用户输入仍从原按键/触摸路径进入。

常规队列最多保留最新一个请求，带输入序号和可行动帧时间戳。冻结期间不执行。成功时清除对应队列项，包括原先绕过普通攻击启动路径的 RUSH/PAR；失败、过期和资源不足都不会转化成强制出招。

连段训练 `INK.Combo.requestStep(0|3|6)` 只记住当前步骤的一次请求。必须等上一步完成要求的真实命中，同时满足原取消或自由行动条件；跨步骤后清空。严格 0F 过早输入会立即拒绝，3F/6F 过早输入仍会到期，不会无限等待。 命中定格中的 3F/6F 请求只记录、不取消，窗口不被消耗；0F 仍不排队。

诊断可读取 `INK.Input.inspect(fighter)`、`fighter._inkInput` 和 `INK.Combo.summary().inputLog`。输入日志限制 200 条，不无限增长。

## 5. 舞的武器与附件

`mai-renderer.js` 使用保留节点绘制扇面、扇缘和扇骨；纸面随径向角展开，而不是沿 Y 轴压缩。`Motion.fanSocket` 与渲染共享手腕、前臂方向和扇柄尺寸。浏览器测试对实际 SVG CTM 与挂点结果做比较，而非只比较两份近似公式。

发辫、腰带和绒球使用限幅曲线形变。附件不扩展武器攻击距离，也不新增身体碰撞点。原有固定武器触及规则保持原样。

本项目历史内部 ID 与中文招名不是直观一一同名，维护时以资产 `gameId`/`name` 为准：

| 原系统 ID | 对应表现 |
|---|---|
| `hissatsu_*` | 龙炎舞，214P，扇尖地面焰弧 |
| `ryuenbu_*` | 飞翔龙炎阵，623K，腿部上升焰 |
| `shinobibachi_*` | 必杀忍蜂，236K，肘部冲刺与翻身 |
| `kachosen_*` | 花蝶扇，236P，扇子投射物仍由原规则负责 |
| `musabi_*` | 空中鼯鼠之舞，空中动作拖尾 |

不要根据内部变量名字把飞翔龙炎阵与龙炎舞的粒子挂点对调。

## 6. 局部与世界特效

`Effects` 每实例持有前、后两个组，12 组带状几何及 144 个粒子路径。局部效果按事件、出生帧与种子重建；缓存用 0.25F 网格，但网格间继续线性插值，再做弧长重采样。缓存满后 FIFO 清除，最多 2048 项。

历史根位置同时记录位置、朝向和比例，避免冲刺时把整条已经走过的轨迹拴回当前身体。世界层在实际移动/命中更新后捕获挂点运动；64 段独立拖尾各有 8F/11F 的有限寿命。瞬移式长跳不生成贯穿画面的巨大连线。取消换招不清除已经发出的世界片段；重置战斗才清空。

局部粒子把初速度、重力和卷曲向量转换到当前根的逆坐标基，保留世界中的发射方向。粒子形状的朝向也随坐标基转换。效果内的运动单位是 SVG 用户单位/模拟帧，而不是屏幕 CSS 像素/秒。

世界池容量 320。优先级由低到高为环境粒子、装饰、接触火花、冲击环、接触核心；满池时高优先级粒子可替换最旧的低优先级粒子，同级不无限扩容。几何路径与节点在初始化后复用。

**编辑缓存**：工坊修改姿势或特效时，`changed()` 立即使特效记录与挂点缓存失效，不能等保存、切换招式后才跟随新位置。对应浏览器回归先读取旧挂点、在界面改姿势，再直接检查新挂点。

## 7. 资产字段

以下字段为可选扩展。校验在保存事务前发生，非法值不会先落盘再报错。

```json
{
  "socket": "fanTip",
  "trailFrames": 9,
  "width": 14,
  "layer": "back",
  "particles": {
    "count": 24,
    "life": 30,
    "speed": 3.2,
    "size": 2.6,
    "spread": 70,
    "species": "petal",
    "gravity": 0.035,
    "drag": 0.04,
    "curl": 3.5
  }
}
```

`trailFrames` 为 2–24，`width` 为 0.3–60，`layer` 为 front/back；gravity 为 −0.6–0.8，drag 为 0–0.4，curl 为 0–16。上述是事件的部分示意，不是一份完整可导入招式。

`clip.meta.secondaryBeats` 最多 64 项，每项 `frame` 不超过动作时长、`amplitude` 有限且绝对值不超过 30。重定时会同步映射这些帧号。

## 8. 实际维护入口

核心数学：`tests/flow4/core.test.js`。浏览器交互：`tests/flow4/browser.py`。舞的完整路线键盘矩阵：`tests/flow4/rhythm_matrix.py`。 全部更新资产的实际折扇挂点矩阵：`tests/flow4/fan_matrix.py`。长时间运行：`tests/flow4/endurance.py`。既有 8 角色机制、状态、投技、左右连段与渲染调度回归仍由 `tools/check_flow.py` 执行。

`tests/fixtures/flow3-combat-contracts.json` 是从用户原包提取的 690 份绑定/判定快照，带原 ZIP 和 game.js 哈希。它是回归合同，不是安全签名。

源码包使用 `tools/package_flow.py`；`tools/check_source_zip.py` 在临时目录解压、校验清单并重新构建两份 HTML。不要在包中放入缓存、浏览器导出的临时大文件或字体文件。

没有将本轮动画转成逐帧位图，未加入网络 API；这些改动仍可通过已有 JSON、SVG 和脚本继续维护。
