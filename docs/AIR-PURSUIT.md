# 击飞后的付费追空

八角色的蹲重拳 cHP 真实命中并把目标打入浮空后，前方向 + F 可以花费 1.5 斗气提前结束当前招并追空。确认窗口为 8 个可行动帧，命中定格不消耗窗口，期间输入可以缓冲。仍须是原挑空招、目标在前方 260 以内且尚在浮空；挥空、被防、扫倒、起身迎击和已自行升空的升龙不开放这个入口。

追空先经过 4 帧可被打断的压身准备，随后以 -9.2 初速起跳。水平推进每行动帧 4.8、总预算 48；朝发动时方向前进，舞台边缘截断，没有目标吸附、无敌或护甲。沿用正常重力，不初始化普通跳跃的转向/快落控制。

起跳后第 2 帧起可选择一次既有空中普通技，使用原动作和判定，伤害为原招 80%，单次命中，不开放必杀、超级技、二次空中攻击或再次追空。实际接触仍检查几何；即使投入资源也可能追丢。追空入口要求目标 juggle 不超过 2，追击接触在 juggle 达到 3 时拒绝，不放宽原有全局浮空限制。

正常落地至少承担 12 帧恢复，挥空也不退款。中途受击沿用普通受击/浮空；若被击倒或被投，清除追空并承担原规则的惩罚，不额外拖欠一次起身恢复。关闭追空不会让已付费角色瞬移回地面。

训练页「挑空追击」提供实际蹲重拳练习、追空和空中普通技按钮。战斗内也显示挑空确认提示；键盘为 S+L 蹲重拳、前+F 追空，之后 K 中拳或 O 重脚。CPU 同样调用公共请求，不直接注入起跳或免费资源。

身体表现读取模拟拥有的准备/飞行/落地阶段，八角色采用各自胸髋与护手路径。表现层不移动根，不改变攻击端点目标，不推进行动时钟，继承原 articulation 上下文。


## CPU 的同入口策略

`DuelBrain.update` 只读取自己真实蹲重拳挑空得到的 `_inkLaunch={source,target,at,used}`。确认延迟按可行动帧计算：困难 3、普通 6、简单 10；许可只有 8 帧，因此简单模式默认不尝试追空，不为 CPU 缩短延迟。每个 source 最多作一次概率抉择，困难 0.65、普通 0.4；共享 `AirPursuit.decision` 合法后，仍通过 `api.request(f,'AIR_CHASE')` 支付资源和执行真实预备动作。hitstop 等待不消耗抉择，过期或拒绝不重复掷概率。

追空序列存在时，CPU 不进入旧空中 planner / special / combo 路径。flight 至少 2 帧、未 `attackUsed` 且无当前攻击时，依据既有延迟 `obs` 的距离和高度选择一次空中普通技：前方 260 内、高差绝对值不超过 150；距离 175 内且高差 85 内选 aMP，其余选 aHK。请求仍走 `api.request`，是否允许与攻击次数由共享战斗门禁决定。观测目标不符合条件则等待，不读对手输入，也不直接读取许可 target 的即时位置来瞄准。

该策略不直接修改 jump、vx、state、资源或许可。windup、flight、interrupted、landing 都隔离旧空中特殊技策略，直到模拟清除 pursuit。`_inkDuel` 只保留最近 source 和有界统计计数，不收集历史列表。

## 本轮检查范围

`qa/air-pursuit/checkpoint.json` 绑定本轮成品。追空真实规则 46 项、输入/按钮/冻结与兼容 7 项、48 个固定种子 CPU 场景汇总 11 项、身体节拍实战 18 项、既有空战 17 项均通过。打断和 juggle 极限中的局部联系规则探针已单独标注，不冒充自然四连。

八角色顺序短时 CPU 采样平均约 1.12–1.35ms、P95 约 1.9–2.6ms，包含模拟、SVG DOM 与特效同步工作；不代表显示帧率、真机性能或长时耐久。707 份原始资产保持不变。本轮阶段存档不结束持续目标。

CPU 还会在近距普通技选择和足够长的对手收招破绽中考虑 cHP，原有风险和启动照常生效。对手招式进度外推使用已观测的 actionTick，避免把命中定格当作招式已经推进。上面的固定种子检查验证接管真实挑空后的决策，并非自然对局选择频率报告。

前 + F 只在追空许可可执行或等待解冻时映射为追空；许可过期、失效或关闭追空后回到原来的斗气冲刺请求，保留旧输入兼容。
