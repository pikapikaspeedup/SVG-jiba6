## 不知火舞图像转 SVG 实验复盘（2026-10-27）

用户认为拼接结果不如原生角色自然，决定回到原有方案。常规首次启动使用原生角色，但用户发现从试用战斗直接进入连段练习时，试用开关没有清除，导致新建角色仍挂上拼接造型。现隐藏新造型试用入口，移除战斗渲染的实验挂载，并让正式 HTML 不再嵌入该实验的运行模块和大体积素材；实验代码与素材保留，用户已有模型、动作和本地工程不作重置。

这次流程是：生成单视角造型参考，将图像描摹成 SVG 路径，再按语义分区和估计关节拆分，绑定游戏骨架，并尝试补画关节、拆分扇叶和接入衣发跟随。结果在单张静态图上更接近目标外观，但实战中出现空白、遮挡错位和缺少原角色的整体动态感，用户认为继续拼凑没有必要。

关键经验：

- **SVG 格式不等于适合动画的模型。** 实验素材没有嵌入位图，但含 19 个分件、约 8,330 条路径；这些大多是参考图的颜色轮廓和裁剪蒙版，不等同于完整、可编辑的解剖与服装部件。路径数量本身也不能证明流畅度好坏。
- **单视角无法提供被遮住的形体。** 手臂、髋部、背面及服装叠层在原图中缺失，切开后靠近似补形只能修补部分姿势；走、转、跳和出招时仍会露出空隙、重复轮廓或比例错位。
- **动态表现来自整套身体设计。** 原生方案的连续肢体轮廓、躯干变形、前后遮挡、表情、扇面和衣发跟随共同服务游戏动作；仅将静态分块旋转到骨点上，无法自动继承这些形变与表现。
- **先验证目标体验，再扩充工具。** 上一次先交付静态试摆，之后又将不完整的拼接版交给用户发现问题；这没有满足“在游戏里看并操作”的目标。今后先在实际游戏的待机、走路、跳跃、转身和代表性出招中检查，再决定是否暴露入口。当前自动化无法控制用户的本地 `file://` 页面，涉及实际画面或流畅度应如实说明并由用户实测确认。
- **试用状态需要有明确的退出边界。** 连段实验室从战斗页直接复用同一个路由，新对战虽然重新创建角色，仍读取了未关闭的试用开关。测试不能只覆盖从试用页返回首页，也要覆盖战斗页直接进入连段练习等实际切换路径。

后续外观改进以现有原生 SVG 人物和动作引擎为基础。AI 图片可作为脸部、发型、配色和服装的设计参考，逐部位重绘可绑定、可遮挡、带必要侧背面的矢量造型，并沿用现有身体、扇面和附件机制；不再把单张参考图自动切片当成完整角色。任何性能结论都需在目标游戏页面实测，不用路径数或离线计算时间代替。
