# FLOW11：从真实输入重新计算对抗

本轮仍在实现中。验收需要同时证明：玩家的实际输入能从规范起点重演；包括隐藏状态在内的首次分歧能定位；同一段操作能做一次边界清楚的 A/B。源码包、随机流、命令通道都是这一轮的组成部分，不额外计作大改进。

## 已采用的设计约束

2026-10-26 已完成本轮唯一一次 Chrome ChatGPT Pro 源码审议。附件含 781 个文件及关键源码全文，Pro 核对了哈希；它没有替我们执行测试。它指出缺少基础 HTML 与旧模块，现已补齐白名单并独立构建验证。后续咨询先运行 `python3 tools/package_engine_review.py <目录> --verify-build`。本轮不补发第二条咨询。

- 从规范新局 S0 重演，不依赖任意对象快照恢复，不用保存的 HP/位置驱动重算。旧 `resetMatch()` 不清全部时钟和残留字段，不能代替规范初始化。
- 外生输入在设备来源聚合之后记录，放在原 `G.tick++` 之前执行，保留同一步内顺序与按钮插入顺序。失败请求也要记录。方向合并为一次采样；设备层需要自己的待提交 held 状态。
- 冻结仍消耗 simulation tick，不能把录带按 actionTick 排序。内部输入缓冲重试、AI、Combo 和训练控制器重新运行，不再作为外部命令重复注入。
- 播放暂停只停调度，不调用会释放按钮和改变蓄力的现场暂停逻辑。强制单步应用命令时遵循运行态语义。
- 源码构建身份、真正生效的资产身份、规则身份分开。工程 revision 不代表内容一致；播放速度不属于战斗规则，rhythm/缓冲/擦身/训练设置属于。
- 权威导出按实际读取依赖划分，不能只选 HP/位置，或因字段带 Visual/FX 就删除。基础姿势转换、AI 历史、输入队列、动态招式参数、离身投射物的攻击引用都可能影响未来。
- 实体稳定 ID 在创建时分配，不能由渲染或首次检查分配。投技共享实体只导出一次；集合/数组是否排序取决于执行语义。
- 每个提交步比较状态组与根摘要，按顺序报告首次分歧，即使后来重新重合。异步 SHA-256 必须接收当步冻结的字节。没有详细轨迹的导入文件不能显示凭空推测的 expected 字段。
- 实时输入与回放输入两层隔离；修改资产/规则或调试状态使严格录制失效或开启明确分支。录完只称“已记录”，实际从 S0 重跑通过才称“验证通过”。

## 当前代码与差距

`src/ink/random.js` 已隔离 AI 战斗随机与装饰；目前两个 AI 共用战斗流，固定顺序下可重现。Pro 建议后续拆角色流及回合派生种子，以便独立诊断，尚未实现。默认新局取系统熵，显式 API 可传 uint32 种子。不要宣称同种子保证 A/B 分支后每次抽样一一对应。

`src/ink/command-stream.js` 是严格白名单的输入事务传输层，含 buttons、move、assist、retreat、neutral。正式模拟包装层已接入 `SVG_FIGHTER.commands`；`SVG_FIGHTER.session.begin(config)` 开启规范会话后，键盘/触控/手柄共用的聚合入口和公开出招 API 会排队到同一通道。普通会话保留旧行为。`session.play(config,tape)` 已能从新局重算命令，但尚未提供带完整身份和状态签名的离线录制格式。模拟内部保持同步返回值。容量目前 3600 步、12000 命令、单步 128 条；到限封存最后完整边界，不把被丢弃的待执行请求写成已执行。完整 UI 需要明确显示停止原因。

`INK.Build` 对当前生产文件闭包签名并内嵌成品，独立源码包重建可得到相同 HTML。已实现有界配置的规范新局；已固定会话有效资产并监控规则变化；仍缺完整状态摘要。

## 剩余实施和验收

1. 规范新局：清时钟、输入计数、实体序号、物理设备、训练控制器、Spacing/Combo 历史，重建角色并固定规则/资产视图。干净页面与经历冻结、投技、投射物的脏页面应产生同一个 S0。
2. 统一外部输入：迁移设备聚合后的事务和公开 API；保持模拟内部调用同步。测试多设备共持、斜方向、PP/KK、按松再按、冻结蓄力释放、失败入队及内部消费。
3. 完整状态与身份：分组导出全局、角色、攻击、投射物、共享投技、输入、随机、AI、训练、Spacing 及战斗姿态来源。对隐藏状态做故意扰动，证明不是等血量改变才发现。
4. 录制/重演格式与界面：有界 JSON，开局前完整验证及身份拒绝，重新运行 AI，逐步签名，暂停与回跳，导入/导出和错误状态。验证跨自然小局与实时输入隔离。
5. 可玩 A/B：先原样验证真实玩家操作，再只改一个白名单变量。固定双方操作与“同人类输入、同种子、自适应 AI”必须区分。原 Spacing 示范的 ready 条件重试不能冒充固定输入录带。

阶段门禁：`python3 tools/check_flow11.py --browser`（先运行 `python3 tests/flow11/build-identity.py` 生成当前包验证）；快速证据核验为 `--evidence`。门禁通过不代表上述剩余项已经完成。目标仍是同浏览器、同构建确定性，不宣称跨平台逐位一致或网络回滚。

## 规范会话与输入迁移阶段证据

`session-config.js` 只接受角色、种子、模式、难度、输入方式、duel/spacing 预设及枚举规则，不接受任意状态补丁。`beginCanonical` 先验证再改变对局，清理旧控制器、物理设备、模拟与输入时钟，并重新创建角色；保留 G.paused 的既有不可删除属性绑定。

会话下的公开输入请求返回入队结果，不承诺立即出招成功；模拟内部仍执行同步请求，缓冲消费不会重复录制。设备聚合使用独立 staged held，解决同一步未提交期间的多设备共持；方向一次应用，按钮顺序不排序。失焦/现场暂停通过 neutral 命令清理，播放 transport 暂停不清持键。

`tests/flow11/session-browser.py` 的 13 项检查通过：旧对局与时钟扰动后的规范新局、残留字段清除、180 步轨迹重演、播放拒绝外部请求、无效招式导入不改变对局、多设备共持、同一步按松再按、播放暂停、600 步 CPU 重算、失焦合并，以及真实浏览器键盘录制重算。这里比较的是测试明确选取的战斗字段，尚不等于完整权威状态签名；手柄经过共用通道，但尚未做本轮实物手柄验证。

## 输入文件身份与资产隔离

`session.export()` 返回 `ink-combat-inputs` v1 对象，`session.load(JSON字符串)` 在改变当前对局前检查构建、有效资产及规则三种 SHA-256 身份。未知字段、未知招式、超限文件或身份不符会拒绝导入。低层 `session.play(config,tape)` 用于测试，不代替文件身份检查。

有效资产从当前覆盖后的模型、骨架和动作内容捕获，独立于工程 revision。会话固定该资产视图，工坊后续编辑留在原工程，停止会话后重新使用原工程；不把编辑中的内容混入正在重演的对局。规则变化会在下一模拟步之前暂停并拒绝导出，播放调度速度不影响规则身份。

规范编码区分 Float64 位表示、负零、undefined 与 null，并保留有语义的数组顺序。新增身份浏览器检查覆盖原样重算、原子拒绝、同 revision 的内容变更、资产视图隔离和规则变化。当前输入文件仍没有完整权威状态轨迹，不能据此宣称重演已经通过逐步一致性验证。

## 实体引用导出阶段

`combat-entities.js` 在真实攻击、投射物和投技创建时分配只读 ID；规范新局重置序号，自然小局沿用序号。`SVG_FIGHTER.entityGraph()` 只读取，保留投射物对已结束攻击的引用，并将双方共享的投技导出为单一实体。投射物 DOM 节点及仅供特效发射器/日志使用的 `_inkTimeline`、`_inkEdges`、`_inkCursor` 不进入战斗数据，集合保留顺序，角色引用以固定索引表示。

这只是完整状态导出的实体部分，尚不包含角色隐藏状态、Spacing 私有缓存、训练控制器等，不是完整验证器。浏览器用远距离显式布局验证投射物离身后的引用；重演测试重新应用相同布局，不声称瞬移已进入输入录带。

## 分组状态检查进展

`SVG_FIGHTER.combatState()` 导出与运行对象脱离的全局、角色、输入计数、战斗随机、Spacing 私有历史、控制器和实体引用数据。字段清单在 `combat-state.js`；包含蓄力、输入队列、完整 AI 对象、基础姿态过渡与模拟姿态速度。角色渲染缩放虽然名字含 render，也参与碰撞坐标，保留在签名中。

`signature` 对各组和根生成摘要；`firstDivergence` 顺序比较每个边界，后续重新一致不抹去首次分歧。`difference` 可对已有完整快照给出字段路径；仅有摘要时只报告变化组，不编造期望字段。当前接口尚未接入有界录制存储、离线验证及用户界面，仍需扩大冻结/投技/跨小局场景和字段覆盖审计，不能以这批检查宣称第二轮完成。
