# INK FLOW 03 — SVG 连续动作、粒子与连段实验室

基于 `pikapikaspeedup/SVG-jiba6` 的 `87a945f48e8b789ed4ad07c7ba53c254120fb2d1`。这是可运行的制作与格斗应用，不是仅有界面的模型。此交付没有写入 GitHub；主分支状态不由本地包改变。

## 先看 15 HIT，再自己练

在首页点 **「体验 15 HIT 长连段」**，肯会用正常出招接口演示。右侧可以选八个角色，每人两条路线，共 16 条。朝向可镜像，演示与跟练共享同一战斗系统。

推荐先选 **0.25× → 节奏入门 · G → 开始跟练**。根据「下一步」和「可衔接」提示按 G；手机点击「G · 发当前步」。G 只是请求当前招式，不会修改血量、延长硬直、免费回能或跳过取消规则。没有按键就不会代打，晚按、错招、能量不足或木桩恢复防御都会失败。

熟悉节奏后切「辅助输入」或「经典搓招」。P1 的 WASD 移动，J/K/L 拳、U/I/O 脚，F 斗气迸发，Q 招架，E 冲击，V 投技，辅助模式 1/2/3 发超级必杀；H 为原战斗招式表。连段页内 R 重置、空格暂停，暂停后可「+1 步」。手动练习不享受演示控制器的自动择时。

基础路线为 10–12 HIT；进阶路线为 14–15 HIT。路线都是**本项目同人格斗规则下的角落路线**，不是官方《街霸 6》连段表。每次初始为六格斗气、三格超级槽；首次命中后木桩自动尝试防御。实测验证同时检查真实伤害、命中计数、资源、首击后防御及左右两侧。

## 本轮改变

### 连续动作，而不是前后两张图切换

`src/ink/inbetween.js` 提供身体轴向转身、头/胸/髋独立角度与侧面厚度。渲染器按连续角度投影肩髋，使用不重叠的不透明裁剪区过渡正/侧/背服装；不是两张半透明角色叠在一起。需要替换前后肢体层级时，将切换安排在侧身遮挡位置。

`core.js` 新增有界三次 Hermite 插值 `spline`。它命中原关键点，单调段不过冲，保留 `strike/load/hold` 的发力与停顿。战斗仍为 60 Hz 离散模拟，显示使用小数帧姿势；伤害和事件不会按渲染刷新率重复触发。命中定格锁在准确接触帧。

690 个兼容资产应用新插值，52 个转身/上升/旋转变体补入独立 yaw 轨道；这不意味着重做了 690 套独立编舞。身体仍是作者设计的二维轮廓与 2.5D 投影，不是三维模型或从单张 SVG 自动猜出的背面。

### 粒子系统，不再给所有招式套同一个圈

`src/ink/particles.js` 是种子随机、解析轨迹、固定容量池的 SVG 粒子类。`effects.js` 分离角色轨迹与世界粒子：火苗、火星、碎片、烟尘、冲击细环、丝带、旋风、三爪切线使用不同形状和运动。拳、脚、肘、身体与弹体挂点分开；冲刺拖尾保留实际世界位置历史；取消后已经发出的世界火星继续衰减。

当前 453 个特效描述都带粒子参数。编辑器「特效」页可改数量、寿命、速度、尺寸、散射角和种类；保存并实战、导出游戏后都保留。单角色效果池 144 个、世界池 320 个；容量满时丢弃额外粒子，不继续创建 DOM。低/标准/高档调整发射数量，不修改战斗。

### 连段训练不是预录录像

`src/ink/combo.js` 管理路线与成功条件，`assets/ink/combos.json` 保存 16 条路线。演示只调用正常 `tryMove`，不写命中和伤害。取消和目押都经过原规则。移除了旧统计中木桩已恢复行动后仍短暂累计的计数宽限。打空、被防、错招、没有完成前一招的必需命中都会中止路线。

右侧展示每步实际命中数、所需指令、当前可衔接提示；底部用真实模拟状态绘制起手/有效/收招/木桩受击条。可以导出本次验证 JSON。摄像机只调整画面，不把玩家搬到新位置或修改碰撞。

## 编辑产物在哪里

```text
assets/ink/characters/<角色>/model.json       形体
assets/ink/characters/<角色>/rig.json         骨架
assets/ink/characters/<角色>/moves/<招>.json  动作、yaw、FX、判定
assets/ink/combos.json                        连段路线
```

例如 `characters/ken/moves/shoryu_2.json` 的 `clip.tracks.yaw` 控制转身，`fx[].particles` 控制粒子。工作台修改后先保存到浏览器工作副本；原生存储被禁用时会明确显示内存提示。此时关闭前必须导出。授权本地 `assets/ink` 目录才可写回本地文件，**保存不是 GitHub 上传**。

当前动作导出、工程导出和「导出游戏」均保留新引擎与连段库。单帧 SVG 只用于检视，不代替动作资产。连段库目前由 JSON 编辑并重新构建，尚无拖拽式连段路线编辑器。修改招式时序/判定后，应重新验证连段，旧路线不保证仍成立。

不知火舞保留兼容 ID 与规范文件名的区别：`ryuenbu_*` 是飞翔龙炎阵（623K），对应 `hishou-ryuuenjin-*.json`；`hissatsu_*` 是地面龙炎舞（214P），对应 `ryuuenbu-*.json`。不要根据旧 ID 的字面名字调换动作。她的长连段使用 OD 地面龙炎舞，不是 OD 忍蜂。

FLOW 03 使用新的浏览器工作副本 ID，避免旧版缓存的动作覆盖新版转身数据。旧工作副本不会删除；旧工程可显式导入；导入同名旧动作会覆盖对应的新轨道，请先导出备份。JSON schema 仍保留版本 2 以兼容既有文件，这与引擎版本 3.0 是不同编号。

## 构建和测试

构建只需要 Python 3.10+ 标准库：

```sh
python tools/build_forge.py
```

测试需要 Node.js 18+、Python Playwright、Pillow 及已安装的 Chromium；测试依赖版本记录在 `requirements-dev.txt`。可用 `INK_CHROMIUM` 指定浏览器路径：

```sh
python tools/check_flow.py
```

旧 `game.js` 保持字节不变。构建器通过唯一源码锚点生成接入层，找不到或出现多个锚点时会失败，不会静默套错补丁。生成文件仍保留原路径，既有 Pages 链接无需改名。

## 更新独立仓库

完整源码包可以作为新的工作目录；更新包只有相对原 main 的修改与新增文件。在你自己的仓库先备份未提交编辑，然后将更新包的内容覆盖到仓库根目录，阅读 `UPDATE-FLOW.md`，构建并验证后正常 `git add / commit / push`。不要把旧源码包中的 `game.js` 或其他历史文件反过来覆盖到新版。

这次没有自动推送，也没有覆盖 main。当前连接可读取新仓库，但没有提供写入动作。项目内的权限说明不等于当前工具能写入。

## 边界

仅验证 Chromium；原生文件夹授权和持久化 API 的契约使用明确测试替身，未冒充实际磁盘授权。同步 JS 计时不包含 paint/GPU；未测试真实手机 FPS、Firefox/Safari、网络回滚、多端联机。角色与动作仍是非官方 2D SVG 同人演绎；八神庵作为跨作品客串，不是 SF6 官方角色声明。作者提供的所有基线与版权告知保留。
